# 基线数据

`scripts/verify_release.py` 拿这里的历史归档重放同样的调用，逐项比对。文件是
`logs/mcporter/` 里的原样拷贝，脚本按文件内「命令：」那一行反解出工具和参数，
文件名不参与解析，随便叫什么都行。

## 选基线只有一条硬规则：数据必须已经定盘

归档的抓取时点如果落在当天 15:00 之前，那份报告里「当日」是盘中快照，而重放是
钉着日期查的收盘值，两者本来就不相等；连带 5/20/60 日的均价、均量、振幅、累计
涨跌全都会跟着差一点。这种差异证明不了任何事，只会把真问题淹掉。

满足下面任一条即可：

- 抓取时点在 15:00 之后（收盘后，当天的 bar 已定）
- 归档命令里的 `date=` 早于抓取那天（查的是往日，与抓取时点无关）

脚本会自己检查这一点（`_captured_intraday`），命中了会在报告里显著标注，但别指望
它兜底——挑基线的时候就该挑对。

## 还缺的

- **medium**：整个归档库里只有一份 medium，抓于盘中 10:35，按上面的规则不能用。
  在部署机上补一份：`python scripts/verify_release.py --only medium --capture`
- **tech**：归档库里那两份都被截断了（JSON 没闭合），脚本会跳过并说明。同样用
  `--capture` 在部署机上补。

`--capture` 只在探活一处维度都不缺时才写文件——拿一份不完整的输出当下次的账本，
只会把当前的故障固化成"正常"。所以补基线要在数据源健康的机器上做。
